# Research-led workflow and comparison agreement

Updated: 2026-11-04

## Owner agreement and stop condition

Ruloom must connect a plain user request to a verified real practice, a suitable
real source, an explicit executable contract, generation, statistical and
practical-use checks, and human review. Source resemblance alone is insufficient.
Gemini performs the product AI roles for Test 1; Claude works independently on
the same task. After the owner reviews Test 1, only a new owner instruction may
start Test 2 with Muse inside Ruloom and a fresh independent Claude run. No Muse
calls, Test 2 launch, or claimed superiority is authorised by this document.

Development workers are separate: the owner-provided AGY Gemini Flash high
session implements; native Claude Sonnet high independently reviews; Codex
coordinates, audits and executes Test 1. Workers cannot delegate to each other
or approve their own changes. Datacore records the evidence in project ruloom.

## First supported product slice

Implement one evidence-backed scalar teaching use case using the existing
HyLogger source and fitted generator. The useful activity is teaching people
to inspect depth-linked inclusion and missing classification-label patterns.
The output is a practice table and measured evidence; no geological prediction,
raw spectral curves, hole coordinates, unique sample identities, real core
photographs, privacy guarantee or source-rights clearance is implied.

Research is bounded to reviewed primary-source evidence in the installed case
catalogue. Runtime AI roles select and explain relevant evidence, assess local
source aggregates, propose supported settings and review measured outcomes.
They cannot invent citations, change the contract or call tools. Code validates
all handoffs and refuses unsupported cases; this is not unrestricted live web
research. Fresh case admission requires retrieved primary evidence and review.

The engine owns domain-neutral orchestration, strict schemas, digests, model
policy, receipts and acceptance. The profile owns field meaning, real-case
records, local profiling, contract requirements and practical-use checkers.
The contract and its source/evidence pins follow the exact candidate into the
report and accepted package; consumer verification must check their presence
and binding. Legacy non-case routes retain their explicitly narrower scope.

The optional image path remains a distinct modality: an image-capable model
may give advisory feedback on supplied or clearly labelled procedural images.
Its opinion cannot replace pixel/link checks or establish geological realism.
Do not advertise a complete multimodal case until its input, generator and
consumer checks exist. Test 1 here is scalar; its result proves no image claim.

  Supports inspecting linked core images and recorded data together; relevant
  to later image cases, not a justification for inventing photographic evidence.

Retain exact evidence identifiers, retrieval date and verifiable supporting
passages or bounded source snapshots. Separate researched facts from our
teaching exercise and modelling choices. Access is not permission to republish.
Inspect actual source columns, finite values, rows and aggregate patterns locally.
Only bounded permitted schema and aggregates go to models; no raw source rows.
A missing required field, unknown evidence identifier, unsupported requirement,
failed role, source change or malformed response stops progression.

## Executable acceptance contract

Freeze requirements before generation. Preserve all calibrated profile checks.
Add independent case checks, never replace or weaken existing checks:

- exact requested rows and declared output columns;
- finite ordered nonnegative depth and source-fitted typical spacing (median of positive adjacent differences; relative difference
  at most 0.01 for this teaching exercise);
- binary inclusion flag (the existing true/false CSV encoding or explicit 0/1);
  inclusion fraction absolute difference at
  most 0.02 from source;
- blank/answered classification-label rates absolute difference at most 0.02
  from source; nonblank labels supported by source;
- a real downstream table read/filter/group summary that accounts for every row
  and explains that labels are interpretations, not measured reflectance;
- complete source, case, contract, role and check receipts with honest limitations.

These exercise tolerances are product choices, not an industry standard.
A required utility failure prevents release even if statistical checks pass.
No seed search, silent retry, hidden failure, changed threshold or AI acceptance.
A model reviewer is advisory; a human still decides whether to accept eligible bytes.

## Test 1: Gemini with Ruloom versus independent Claude

Use a new frozen trial directory under ignored runs. Before either route starts,
save the exact human-style prompt, input hashes, evidence pack, output schema,
check definitions, limits and scoring protocol. Both routes receive the same
request, source access, evidence and contract. Independent Claude starts fresh,
without Ruloom code, implementations, outputs, reviews or helper-session history.
Use an explicit configured Claude model and effort and record observed identity.
Its own Python generation is allowed; it cannot import or call Ruloom.

Ruloom uses explicitly configured Gemini roles, with each actual call recorded.
Evaluate both candidates with the same frozen independent scorer. Report source
fitness, fulfilled requirements, statistical results, downstream usefulness,
limitations, refusals, calls, elapsed time and available usage/cost evidence.
Record unavailable cost as unavailable. State unequal tools/context or budgets.
Keep all attempts. A single paired trial is a case result, not general superiority.
A same-model baseline is a future optional control, not a hidden substitute for
this owner-requested cross-model comparison.

Test 1 is proven operational only after code review, independent audit, full
gates, a fresh successful Ruloom route, correctly scored independent baseline,
negative controls and recipient verification. If the case fails, retain the
failure, repair under review and label any rerun; never relabel it a first pass.
End after the Test 1 report. Test 2 remains awaiting explicit owner instruction.

## Delivery focus and merge cadence

Owner priority confirmed on 4 November: work mainly on the HyLogger profile.
Deliver small coherent slices: (1) admitted primary evidence, source-fit and
practical-use checking in the profile; (2) binding those checks into the existing
engine, human gate, release and recipient verification; (3) checked runtime AI
roles and fresh-user orchestration; (4) the frozen Test 1 report. Independently
review and audit each slice, require green CI and branch protection, then merge
to main regularly. An earlier slice is a foundation, not a ready full workflow.
No separate generation/release engine, benchmark-specific source/row hardcoding,
automatic seed search or arbitrary contract overrides are permitted.
