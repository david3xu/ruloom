## Findings

**M1 — Medium: AGY accepts a reply that never names the model, although the file says "no fallback".**
- **Where:** `models/agy_cli.py:144-148`; the file and class docs say "no fallback".
- **Probe p2:** a stream with no `init` event, or an `init` without `model`, is ACCEPTED. `Usage.model` is "unknown", and the data are returned. A stream naming a different model is correctly refused.
- **Effect:** the evidence is truthful, because the report shows "reported model: unknown". But a draft or plan can still come from a model whose identity was never observed. Only `scripts/provider_smoke.py` (live-planner stage, `provider_smoke.py:146-152`) fails closed on this, and that script is opt-in.
- **Minimal rework:** refuse a missing or unknown `init.model` in the product path, or state this acceptance explicitly in `docs/model-families.md` and the evidence report. Which one is the owner's call.

**L1 — Low: GPT effort rule is inconsistent.** `family_default` allows GPT at medium effort only (`models/selection.py:28-29`), but `validate_selection` accepts `gpt-oss-120b-high` with effort high (probe p1). `--role-family planner=gpt` with no effort fails because the AGY default effort is high; the error does not tell the user to pass `--role-effort planner=medium`.

**L2 — Low: error text can carry model output.** AGY schema failures put the full multi-line jsonschema message, including the offending instance, into `ModelError` (probe p2). That text goes to `model_call_failed` in `run.jsonl` and the report. A malformed reply could therefore put model-authored text into the evidence.

**L3 — Low: unbounded reads.**
- `AgyCLIModel.complete` buffers all subprocess stdout with no cap.
- `prepare_request` reads the whole source with `read_bytes()` to hash it (`request.py:143`).
- The first is bounded in practice by the timeout, the second by the source size.

**L4 — Low: `scripts/provider_smoke.py` has no automated test.** It is referenced only in `docs/model-families.md:86`, so its assertions (`offline*` makes no model call, the planner reports the selected identity, a decline writes no release) were not exercised. I read it and found no logic error.
